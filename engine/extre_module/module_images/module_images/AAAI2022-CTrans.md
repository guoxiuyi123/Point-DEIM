# Channel-wise Cross Fusion Transformer (CCT) 模块总结

---

## 1. 动机

### 现有方法的问题

U-Net 的跳跃连接采用**简单复制拼接**的方式将编码器特征传递给解码器，但这种方式存在严重缺陷：

- **语义鸿沟问题**：编码器各层特征之间存在多尺度语义差距，编码器与解码器之间也存在语义不一致，简单拼接无法弥合这些差距 [2][6]
- **并非所有跳跃连接都有益**：实验表明，某些跳跃连接反而会**损害**分割性能（例如在 GlaS 数据集上，仅保留 L1 的效果比完全不用跳跃连接还差）[6]
- **无跳跃连接可能更优**：在部分数据集上，完全去掉跳跃连接的 U-Net 表现甚至优于原始 U-Net，说明简单复制的特征融合方式本身就不合适 [6]
- **现有改进方法不足**：UNet++ 通过密集嵌套路径、MultiResUNet 通过残差路径来缓解语义差距，但它们仍然无法充分利用全尺度信息，也无法捕获非局部的语义依赖关系 [3][5]

### 提出 CCT 的目的

设计一种能够从**通道维度**出发，利用 Transformer 的长距离依赖建模能力，对多尺度编码器特征进行**自适应跨通道交互融合**，从而替代原始跳跃连接中低效的简单拼接操作。[3][7]

---

## 2. 工作原理与核心思想

### 核心思想

> 不同通道关注不同的语义模式，CCT 通过沿**通道轴**（而非传统的 Patch 轴）执行交叉注意力，实现多尺度特征之间的**协同学习**，而非独立连接。[3][7]

### 工作流程

CCT 模块包含三个步骤：

#### 步骤一：多尺度特征嵌入（Multi-scale Feature Embedding）

将编码器四个层级的输出 $$E_i \in \mathbb{R}^{\frac{HW}{i^2} \times C_i}, \quad i=1,2,3,4$$ 分别以不同的 Patch 大小（$$P, \frac{P}{2}, \frac{P}{4}, \frac{P}{8}$$）进行 tokenization，使得不同尺度的 Patch 映射到编码器特征的相同区域。保留原始通道维度，然后将四个层级的 token 拼接为统一的 Key 和 Value：

$$T_\Sigma = \text{Concat}(T_1, T_2, T_3, T_4)$$

[7]

#### 步骤二：多头通道交叉注意力（Multi-head Channel-wise Cross Attention）

这是 CCT 的核心操作。设计**五个输入**：四个层级的 token $$T_i$$ 分别作为 Query，拼接后的 $$T_\Sigma$$ 作为 Key 和 Value：

$$Q_i = T_i W_{Q_i}, \quad K = T_\Sigma W_K, \quad V = T_\Sigma W_V$$

其中 $$W_{Q_i} \in \mathbb{R}^{C_i \times d}$$，$$W_K \in \mathbb{R}^{C_\Sigma \times d}$$，$$W_V \in \mathbb{R}^{C_\Sigma \times d}$$，$$d$$ 为序列长度（Patch 数量）。[8]

交叉注意力计算如下：

$$CA_i = \sigma\left[\psi\left(\frac{W_{Q_i}^\top T_i^\top \cdot T_\Sigma W_K}{\sqrt{C_\Sigma}}\right)\right] W_V^\top T_\Sigma^\top$$

其中 $$\psi(\cdot)$$ 为实例归一化（Instance Normalization），$$\sigma(\cdot)$$ 为 Softmax 函数。[9]

**与传统自注意力的关键区别**（见下图对比）：

| 特性 | 传统自注意力 | CCT 通道交叉注意力 |
|------|:---:|:---:|
| 注意力方向 | Patch 轴 | **通道轴** |
| 输入来源 | 单一尺度 | **多尺度跨层级** |
| Query 与 Key | 相同来源 | **不同来源（交叉）** |
| 归一化方式 | Layer Norm | **Instance Norm** |

[7][9]

多头注意力的输出为各头的平均：

$$MCA_i = \frac{1}{N}\sum_{n=1}^{N} CA_i^n$$

[9]

#### 步骤三：MLP + 残差连接

对多头注意力输出施加 MLP 和残差操作：

$$O_i = MCA_i + \text{MLP}(Q_i + MCA_i)$$

该操作重复 $$L$$ 次构建 $$L$$ 层 Transformer。实验中 $$N=4$$（头数），$$L=4$$（层数）为最优配置。最终四个输出 $$O_1, O_2, O_3, O_4$$ 经过上采样和卷积后，与解码器特征拼接。[9]

### 直觉理解

可以将 CCT 理解为：**每个编码器层级的特征（Query）都在"询问"所有层级的联合特征（Key/Value），从通道维度学习"哪些通道的哪些尺度信息对我最有用"**，从而实现自适应的多尺度通道融合。

---

## 3. 总结

| 方面 | 要点 |
|------|------|
| **解决的问题** | U-Net 跳跃连接中简单复制导致的多尺度语义鸿沟 |
| **核心创新** | 沿通道轴（而非 Patch 轴）执行交叉注意力，实现多尺度编码器特征的协同融合 |
| **技术手段** | 多尺度特征嵌入 → 多头通道交叉注意力 → MLP 残差精炼 |
| **关键设计** | 使用 Instance Normalization 平滑梯度传播；四个 Query 对应一个共享 Key/Value 实现跨尺度交互 |
| **实验验证** | 消融实验表明仅加入 CCT 即可在 GlaS 上提升 **+3.64% Dice**，在 MoNuSeg 上提升 **+2.86% Dice** [13] |
| **注意力可视化** | 交叉注意力矩阵揭示了不同数据集中不同编码器层级的重要性差异，与跳跃连接分析结论一致 [13][14] |

CCT 模块的本质是将 Transformer 的全局建模能力引入**通道维度的多尺度特征融合**，以一种数据驱动的自适应方式替代了 U-Net 中固定的、独立的跳跃连接，从根本上解决了编码器多尺度特征之间的语义差距问题。[3][7][14]
